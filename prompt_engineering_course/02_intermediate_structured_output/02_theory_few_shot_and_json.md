# 结构化输出与 Few-Shot 提示词

我们在开发业务系统时，往往不能直接把大模型生成的文字展示给用户，而是需要大模型帮我们**提取数据**，然后存入数据库。
这就要求模型必须输出严格格式化的数据（比如 JSON）。

## 1. 痛点：如何让大模型乖乖听话？

如果你只对模型说："请提取订单信息，格式如下：姓名，电话，地址"，模型可能会回复：
> "好的，没问题。提取的订单信息如下：
> 姓名：张三
> 电话：123
> 地址：北京"

这段包含了前言后语的文本，在代码里用 `json.loads()` 解析会直接报错。我们需要它返回**纯正的 JSON 字符串**。

## 2. 解决方案一：JSON Prompting + 强制模式

现在的 OpenAI 模型原生支持强迫输出 JSON。但即便如此，你仍然需要在 Prompt 中清晰地定义你想要的 JSON 结构（类似于你在 Tools 中定义的 Schema）。

```markdown
# 错误示范
请把文本提取为 JSON。

# 正确示范
请提取文本中的信息。你必须且只能输出合法的 JSON 字符串。
不要输出任何 Markdown 标记（例如 ```json ），也不要输出任何解释性文字。
JSON 结构必须严格符合以下字段要求：
{
  "user_name": "字符串，如果没有则为 null",
  "phone": "字符串，提取连续的数字，如果没有则为 null",
  "items": ["商品名称列表"]
}
```

## 3. 终极绝招：Few-Shot (少样本提示)

即便你写了非常详细的说明，模型（尤其是小模型）依然可能在复杂场景下出错。
**Few-Shot** 是目前最有效的 Prompt 技巧之一：直接在 Prompt 里给它几个**真实的输入输出例子**。

> **人类学习也是一样的，看十遍理论，不如看两个例子。**

在 Prompt 中加入 Few-shot 示例：

```markdown
# 示例 1
输入："李四昨天在淘宝买了两箱苹果和一根香蕉，电话是13800000000。"
输出：
{
  "user_name": "李四",
  "phone": "13800000000",
  "items": ["苹果", "香蕉"]
}

# 示例 2
输入："王五想订个外卖。"
输出：
{
  "user_name": "王五",
  "phone": null,
  "items": []
}
```

通过 Few-shot，模型瞬间就明白了你的意图，它甚至不需要阅读冗长的规则，就能完美照着你的格式输出。
